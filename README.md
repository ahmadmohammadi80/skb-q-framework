# SKB-Q: Structural Knowledge Bridge for Auditable Mixed-Precision Quantization

**Research artifact repository for the SKB-Q framework.**

SKB-Q is designed as a thin, auditable module for structure-aware mixed-precision quantization of transformer language models. The repository is intended to support reproducible research and to separate **validated experimental artifacts** from intermediate or illustrative outputs.

> **Reproducibility status:** This repository currently contains the project scaffold and documentation. Any sensitivity scores, bit allocations, accuracy/perplexity results, or benchmark claims must be generated by the calibration-based evaluation pipeline before being treated as validated experimental results.

## Research scope

The artifact is organized around four stages:

1. **Operator-graph extraction** — recover the model's module/operator structure.
2. **Structural feature construction** — derive auditable node-level features from the graph.
3. **Calibration-based sensitivity estimation** — estimate the effect of quantization choices using real calibration data rather than placeholder scores.
4. **Bit allocation and evaluation** — apply the allocation policy and evaluate memory/compute trade-offs and model quality.

The current research baseline is **OPT-125M (`facebook/opt-125m`)**. Larger models should be added only after the pipeline has been validated end-to-end.

## Existing project artifacts

Earlier development produced an OPT-125M operator graph and derived feature/sensitivity files. These should be treated as **development artifacts** until the sensitivity values have been regenerated with the real calibration procedure.

In particular, do not interpret a file named `*_sensitivity_dataset.json` as experimental evidence unless its provenance records the calibration dataset, perturbation/quantization procedure, random seeds, software versions, and evaluation metrics.

## Reproducibility protocol

Every validated experiment should record:

- base model identifier and revision/commit;
- tokenizer identifier and revision;
- calibration dataset and split;
- number of calibration samples and sequence length;
- quantization backend and algorithm;
- candidate bit widths;
- sensitivity definition and perturbation procedure;
- allocation objective and constraints;
- random seeds;
- software and hardware environment;
- evaluation metrics and raw outputs.

Generated JSON/CSV artifacts should include enough metadata to trace them back to the exact configuration used to produce them.

## Hugging Face artifact

The Hugging Face companion repository should contain **data and model artifacts only**, not replace this source-code repository. The recommended linkage is:

```text
Paper
  │
  ├── GitHub: code + configs + reproducibility instructions
  │
  └── Hugging Face: model/data artifacts + machine-readable outputs
          │
          └── Release tag / DOI snapshot
```

The Hugging Face repository should be created only after the corresponding artifacts are validated. Placeholder sensitivity values must not be uploaded as if they were measured results.
